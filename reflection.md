1. Instance Independence: Each instance should have its own attribute values so that changing one object does not accidentally change another. For example, imagine two creature cards in a Magic: The Gathering match: Goblin A has 3 power and Goblin B has 2 power. If both creatures accidentally shared the same power attribute, giving Goblin A a +2/+2 boost would also make Goblin B become 4 power. This could cause a critical gameplay bug because the game would no longer correctly track each creature's individual state. Independent instance attributes make sure every creature keeps its own power, toughness, abilities, and other information.

2. Parameter Architecture: The self parameter represents the specific object being created or used. In the __init__() method, self allows Python to store values inside that particular instance, such as self.name or self.score. Python requires self to be written explicitly because it makes it clear which object the method is operating on. For example, card.name means the name belongs to that specific card object. Other programming languages may hide this reference, but Python makes it visible to help make the code easier to understand.

3. Class Attributes vs. Instance Attributes: A class attribute is shared by objects unless an instance creates its own version. For example, changing MagicCard.DEFAULT_SET = "Zendikar" changes the class attribute, so instances that do not have their own DEFAULT_SET will see "Zendikar". However, if we write card.DEFAULT_SET = "Innistrad", Python creates an instance attribute for that specific card. This is called shadowing because the instance's attribute hides the class attribute when accessed through that instance. Shadowing can make code harder to predict if programmers do not realize that an instance has its own value.
